# BoatLoad - Developer Onboarding Guide

Welcome to the **BoatLoad** codebase! This document provides a comprehensive overview of the project's architecture, file structure, and implementation details to help you get up to speed quickly.

## Architectural Overview

BoatLoad is a 3D web game built using **Three.js**. The game is structured around a finite state machine (FSM) that manages distinct gameplay phases (e.g., Dock, Shipyard, Obstacle sailing). 

The core gameplay loops involve:
1. **Shipyard Phase:** A voxel-based editing mode where the player repairs damage to a ship using various tools (hammer, rope, needle). The ship is represented as a 3D voxel grid.
2. **Obstacle Phase:** An arcade-style sailing mode where the player steers the ship to avoid obstacles. The ship is subjected to physical damage which modifies the underlying voxel grid, potentially causing it to sink.

## Directory & File Structure

The source code is contained entirely within the `src/` directory, broken down into functional domains.

### 1. Root Application Files (`src/`)
- **`main.js`**: The main entry point of the application. It initializes the Three.js scene, camera, and renderer. It is responsible for loading global assets (e.g., GLTF models for ships, fish, and rocks) and bootstrapping the `GameState` machine. The main render loop (`tick()`) is defined here.
- **`style.css`**: Global CSS styles for the overarching application layout (HTML overlay elements).
- **`counter.js`**: A simple utility script (often generated by Vite templates) for DOM counter examples.

### 2. Core Game Logic (`src/core/`)
Contains the central state management and configuration loading systems.
- **`GameState.js`**: The backbone of the game. Implements a Finite State Machine managing transitions between `DOCK`, `SHIPYARD`, `OBSTACLE`, and `RESULTS` phases. It owns phase-specific managers and ensures clean teardown of memory/events when switching modes.
- **`EventBus.js`**: A lightweight, global event emitter (pub/sub pattern). Used to decouple systems (e.g., UI components trigger events that the GameState listens to).
- **`LevelConfig.js`**: Responsible for fetching and parsing level definitions (e.g., `day1.json`). It dictates the required repairs, spawned obstacles, and environmental factors for each day.

### 3. Voxel Shipyard System (`src/shipyard/`)
Handles the logic, rendering, and interaction for the voxel-based ship repair phase.
- **`VoxelGrid.js`**: The core data structure representing the ship. A 3D grid storing the `CellState` (e.g., `EMPTY`, `INTACT`, `MISSING`, `DAMAGED`) and color for every voxel.
- **`ShipBuilder.js`**: Translates GLTF models and JSON configuration into a `VoxelGrid`. It maps predefined zones (like hull, mast, sails) and applies initial damage based on the `LevelConfig`.
- **`ChunkRenderer.js`**: Highly optimized Three.js renderer for the `VoxelGrid`. Uses `InstancedMesh` for intact voxels to minimize draw calls, while spawning individual meshes for damaged/missing cells (highlighted with distinct materials) to allow for visual feedback.
- **`BuildSystem.js`**: Manages user interaction for placing new blocks (repairs). It tracks the active blueprint, handles block rotation, and renders a "ghost" mesh for placement previews.
- **`ShipRaycaster.js`**: A custom, optimized BVH (Bounding Volume Hierarchy) raycaster. It calculates pointer intersections against the voxel grid efficiently so the user can click on specific cells to repair them.
- **`DamageSystem.js`**: Utility for calculating and applying structural damage to the voxel grid during gameplay.

### 4. Obstacle Sailing Phase (`src/obstacle/`)
Handles the arcade-style sailing mechanics.
- **`PlayerShip.js`**: The player's avatar during the sailing phase. It wraps the `ChunkRenderer` to display the voxel ship, manages steering/physics, and dynamically updates its Y-position and pitch/roll to ride the ocean waves. It also tracks the `waterLevel` and manages sinking logic if `MISSING` cells fall below the waterline.
- **`ObstacleManager.js`**: Spawns and recycles obstacles (e.g., rocks, seaweed) as the ship sails forward. Handles bounding box collision detection between obstacles and the `PlayerShip`.
- **`QTESystem.js`**: Quick Time Event system for specific mid-gameplay interactions or repairing on-the-fly.

### 5. Environment & VFX (`src/environment/`)
Handles the background aesthetics, lighting, and ambient creatures.
- **`Ocean.js`**: A custom shader-based ocean material applied to a large `PlaneGeometry`. It calculates complex wave heights using superimposed sine waves based on time. It exposes `getWaveInfo(x, z)` so physics objects can ride the surface.
- **`EnvironmentManager.js`**: Spawns ambient environmental details (like random fish swimming around) to make the ocean feel alive.
- **`FishAnimator.js`**: A procedural animation system for aquatic life. Instead of relying on pre-baked skeletal animations, it calculates procedural sine-wave deformations and squash-and-stretch scales on the fish bones (e.g., Spine, Tail) to simulate swimming.
- **`SharkSkinRepair.js`**: A specific utility for repairing skeletal hierarchies or missing vertex weights on dynamically loaded shark/fish models to ensure they deform correctly under `FishAnimator`.

### 6. User Interface (`src/ui/`)
Manages the HTML/CSS overlay systems that sit on top of the Three.js canvas.
- **`HUD.js`**: The Heads-Up Display for the sailing phase (health bars, score, steering indicators).
- **`BuildMenu.js`**: The UI for selecting repair materials (blueprints) in the shipyard.
- **`DocketSheet.js`**: Displays the list of required repairs for the current day during the shipyard phase.
- **`DialogueBox.js`**: System for displaying NPC dialogue or tutorial prompts.
- **`ui.css`**: Specific stylesheets for the UI components.

### 7. Utilities (`src/utils/`)
- **`AudioManager.js`**: Wrapper for the Web Audio API to handle sound effects and background music.
- **`MathUtils.js`**: Common mathematical helper functions (lerping, clamping).

### 8. Assets (`src/assets/`)
Contains all static configurations and 3D models required by the game.
- **Models (`ships/`, `creatures/`):** e.g., `sloop.glb` (Ship models), `shark.glb` (Fish models).
- **Configurations (`ships/`):** e.g., `sloop.json` (defines grid dimensions and bounding zones for voxelization).
- **Levels (`levels/`):** e.g., `day1.json` (defines day progression, obstacles, and initial damage).

## Implementation Details & Highlights

- **Voxel Optimization:** Because ships can consist of tens of thousands of voxels, `ChunkRenderer` leverages `THREE.InstancedMesh`. This allows the entire intact hull to be drawn in a single draw call to the GPU. Only cells that require unique states (like highlighting missing patches in red) are spawned as individual meshes.
- **Wave Physics:** The ocean relies on a vertex shader for visual displacement. To allow the `PlayerShip` to physically interact with this visual effect, the same mathematical sine wave formula used in the GLSL shader is duplicated in JavaScript within `Ocean.getWaveInfo()`. The ship queries this function to perfectly align its pitch, roll, and height with the visual wave surface.
- **Sinking Mechanics:** The ship's buoyancy is dynamically tied to its voxel integrity. During the obstacle phase, `PlayerShip` counts the number of `MISSING` cells that fall below its waterline. If holes are present, an internal water plane rises, and the entire ship mesh is pushed downwards into the ocean until it sinks.
- **Procedural Animation:** To save asset size and complexity, ambient creatures like fish do not use pre-animated keyframes. Instead, `FishAnimator.js` finds specific bones (like "Spine1", "Tail") in the GLTF skeleton and applies continuous mathematical rotations based on time, creating a realistic, infinitely varied swimming motion without animator overhead.
